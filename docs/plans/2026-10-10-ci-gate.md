# Plan：CI 閘（compile ＋ python 靜態檢查）— 一個指令講真話

- 觸發：SK 10-10 授權自主完成 packai 所有目標功能；工作次序第 2 項＝「E1：加 CI（compile ＋ python checks gate）」。
- 現況（已親核）：repo **冇** `.github/workflows/`、**冇** 統一 runner。`tests/check_*.py` 共 **127 個**（`tests/*.py` 130 個減 3 個工具：`_r5_patch_lang.py`／`gen_reply_lang_json.py`／`update_reply_prompts.py`）。每次都要人手跑 for-loop（AGENTS.md Commands 段），而且「1 個已知紅」（`check_ask_display_leak.py` 需真機 `latest.log`）要人手記住，唔記得就會誤判 regress。Java 側閘＝`gradlew compileJava compileTestJava` ＋ init-script harness。

## 1. 問題（一句）

綠／紅嘅判斷散喺三段人手命令＋一個要記住嘅已知紅；冇一個指令可以答「而家棵樹係唔係綠」。

## 2. 設計（本機優先，零新依賴）

**主體 = `tools/ci_gate.py`**（純 Python 標準庫，`subprocess` 驅動，唔加套件）：

1. **靜態檢查段（default 開）**：逐個 `tests/check_*.py` 跑，收集 RC／輸出頭幾行。
   - 已知紅清單＝**資料檔** `tools/ci_known_red.txt`（一行一檔名＋原因），唔硬編碼落 code。
   - 不在清單而紅 ⇒ **FAIL**；在清單而變綠 ⇒ 只印 info（提醒可移除），唔當失敗。
   - 清單檔唔存在／有指向唔存在嘅檔 ⇒ FAIL（防止靜默失效）。
2. **Compile 段（`--compile`）**：`forge/1.19.2` 下 `gradlew.bat compileJava compileTestJava --console=plain`，JDK 由 `-Dorg.gradle.java.home=`（路徑預設讀 `AGENTS.md` 記住嘅 eclipse_adoptium-17；可用 `--java-home` 覆蓋）。
3. **Harness 段（`--harness`，默認關）**：`gradlew.bat -I tmp-check.gradle <task>`（`tmp-check.gradle` 係生成物、唔入 git，所以段前要確認存在，唔存在就 FAIL 並提示 `python research/gen_tmp_check.py`）。
4. 總結表：每段 PASS／FAIL、數目（跑幾多個 check／紅幾個）、總 RC。

**可選（唔係今次必做）**：`.github/workflows/static-checks.yml` 只跑第 1 段（唔跑 gradle ⇒ 唔需要網絡依賴同 JDK 設定）。風險註明：未在 GH runner 實測過、未必有需要（本機優先、SK 成本敏感）。

## 5. 驗收標準

- **V1** 工作樹乾淨時 `python tools/ci_gate.py` ⇒ RC=0，輸出有「跑咗 N 個 check、M 個在已知紅清單」數字。
- **V2** **負控（必做）**：故意令一個原本綠嘅 check 紅（在 `%TEMP%` 影子副本上做，唔郁 repo）⇒ RC=1 並且指名邊個檔。證明個閘真會紅（skill `negative-control-verification`）。
- **V3** 已知紅清單失效測試：把清單改成一個唔存在嘅檔名 ⇒ RC=1。
- **V4** Baseline 對得上實測（127 個 `check_*.py`、1 個已知紅）。
- **V5** `git status` 只准見到上述 4 個新檔；`forge/`／`neoforge/` 零改動。
- **V6** 靜態段單獨執行 < 60 s（實測記錄）。

## 6. 風險／還原
