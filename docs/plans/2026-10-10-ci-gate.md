## 2. 設計（本機優先，零新依賴）

**主體 = `tools/ci_gate.py`**（純標準庫，`subprocess` 驅動）：

1. **靜態檢查段（default 開）**
   - `ROOT` = repo root（由 script 位置推導，**唔靠 caller cwd**）；逐個 `tests/check_*.py` 以 `subprocess(..., cwd=ROOT)` 跑，收 RC＋輸出首行。
   - 檔數**runtime glob** 計（唔硬編碼）；亦唔准 `git add -A` 之餘新增 check 就被靜默漏跑。
   - 已知紅＝**資料檔** `tools/ci_known_red.txt`，格式 `<檔名>\t<允許RC>\t<原因>`（Tab 分隔；`#` 開頭為註解）。
     - 唔在清單而 RC≠0 ⇒ **FAIL**。
     - 在清單但 **RC≠允許值** ⇒ **FAIL**（即只准 RC=2；RC=1 真 leak 一律紅）。
     - 清單條目：檔唔存在／RC 唔係 2／原因空白 ⇒ **FAIL**（防清單腐化）。
     - 在清單而變綠 ⇒ 只印 info（提醒可移除），唔當失敗。
2. **Compile 段（`--compile`）**：`forge/1.19.2` 下 `gradlew.bat compileJava compileTestJava --rerun-tasks --console=plain -Dorg.gradle.java.home=<javaHome>`；java-home 解析次序＝`--java-home` > `JAVA_HOME` > 預設（預設路徑照 AGENTS.md：`C:/Users/skps9/.gradle/jdks/eclipse_adoptium-17-amd64-windows.2`），**驗證存在**，唔存在＝段內 FAIL 並印清楚訊息（唔會當「靜默通過」）。
3. **Harness 段（`--harness`，默認關）**：先檢查 **`forge/1.19.2/tmp-check.gradle`** 存在（唔存在＝FAIL 並提示 `python research/gen_tmp_check.py`）；然後由該檔抽 `run*Check` 任務名一次過跑（**唔准**自己加 `run` 前綴）。
4. 總結表：每段 PASS／FAIL、跑咗幾多個 check／幾個在清單、總 RC。

**唔做**：GH Actions（A7 理由）；唔取代 gradle／唔加打包；唔自動 commit／唔部署 jar；唔改任何 product code／唔改 `tests/check_*.py` 斷言；唔加 git hook。

## 4. 驗收標準

- **V1** 乾淨樹 `python tools/ci_gate.py` ⇒ RC=0；輸出有「跑咗 N 個 check（runtime 計）／清單 1 個」。
- **V2** `cd tests && python ../tools/ci_gate.py` ⇒ 仍 RC=0（證 cwd 已由 gate 自己處理）。
- **V3a** allowlist 指向唔存在嘅檔 ⇒ RC=1。
- **V3b（真負控）** 喺 `%TEMP%\ci_negctl\` 建影子 repo（`tests\check_ask_display_leak.py` 回 **RC=1** ＋ `tools\ci_known_red.txt` 同一條目），跑 `python tools/ci_gate.py --root <影子>` ⇒ gate 必須 **FAIL**（RC=1 唔會被允許值 2 放行）；同一影子改成 `sys.exit(2)` ⇒ 必須 RC=0。證明分級真生效。
- **V3c（真負控）** 令一個原本綠嘅 check 紅 ⇒ gate FAIL 並指名該檔。
- **V4** baseline 以**當日實跑**為準（10-10 = 128 個、1 已知紅）；gate 不得硬編碼數字。
- **V5** `git status` 只准上述 4 個新檔；`forge/`／`neoforge/` 零改動。
- **V6** 靜態段單獨 < 60 s（實測記錄）。
- **V7** `--compile` 段：正常樹 RC=0；**故意傳唔存在嘅 `--java-home`** ⇒ 該段 FAIL 且訊息清楚（唔可以靜默當過）。
